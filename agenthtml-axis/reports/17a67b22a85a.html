The challenge

One KPI. Too much array ceremony.

Row 6 walks the week left-to-right and only fills quotas for days with sales. E1 should always surface the progressive daily quota so far — the last non-zero entry in B6:H6 — preferably as a normal formula, not CSE array magic.

Replace nested array logic with a classic LOOKUP trick.

The shortened formula builds a reciprocal mask of non-zeros, then asks LOOKUP for an impossibly large lookup value so it lands on the last numeric 1.

Why LOOKUP(2, 1/(…)) works

Build a mask

B6:H6<>0 becomes TRUE/FALSE for filled quota days.

Reciprocal vector

1/(…) turns TRUE→1 and FALSE→#DIV/0!, which LOOKUP ignores.

Overshoot lookup

Lookup value 2 is larger than any 1, so LOOKUP settles on the last 1.

Return paired value

Result vector B6:H6 yields the matching latest quota for the header metric.

FAQ

Questions auditors ask next.

Quick answers about semantics, edge cases, and delivery constraints.

What exactly was wrong with the provided INDEX formula?

Nothing mathematically fatal — it finds the rightmost non-zero column position and indexes into B6:H6. The task asked to shorten that pattern. It is verbose, depends on column number arithmetic, and was stored as an array formula in the input workbook.

Does LOOKUP require sorted data here?

The classic “LOOKUP big number in a 1/condition mask” pattern intentionally relies on LOOKUP’s approximate-match behavior. Because successful matches are 1s and failures become errors that are skipped, the oversize lookup value 2 lands on the last valid 1.

What happens mid-week when more sales land?

As soon as a later day in row 5 becomes non-zero, its row-6 quota formula activates and E1 automatically advances to that newer non-zero quota. No formula edit required.

Why not TAKE/FILTER/XLOOKUP?

Modern dynamic-array functions could also express “last non-blank/non-zero”, but LOOKUP stays short, widely compatible with older desktop Excel, and matches the spirit of shrinking the legacy array formula.
