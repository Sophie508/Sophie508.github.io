Case 01 — XSS Filter Bypass

The parser that
looked away.

A DevOps sanitizer strips every <script>, every dangerous tag, and every on* handler from an HTML file. The task: hand it a document that still fires alert() automatically once it reaches a browser. The winning move exploits not a missing rule, but a blind spot — the filter and the browser disagree about where a comment ends.

01The defense & its blind spot

/app/filter.py parses HTML with BeautifulSoup and rewrites the file in place. The agent read it once and inferred three enforcement rules — and, eventually, the one thing it never touches.

Rule 01 — Tags

Removes all <script> elements via soup("script"), regardless of type.

Rule 02 — Frames

Deletes <frame>, <iframe>, <object> and <embed> nodes.

Rule 03 — Handlers

Walks every element and deletes any attribute where attr.startswith("on") — onclick, onerror, onload…

✕ The gap

It iterates find_all(True) — element nodes only. Comment nodes are never inspected. Anything inside a comment passes through untouched.

03Why nearly everything failed

The task hides two gates. A payload must clear both. Almost every vector the agent tried cleared exactly one — and the search was really a hunt for something that clears both at once.

gate i

Survive the filter

Not stripped by BeautifulSoup. Easy to pass with obscure attributes or namespaces — but that alone does nothing in a browser.

gate ii

Auto-execute in the browser

Fire alert() with zero user interaction — no click, no focus. Rules out most surviving-but-inert tricks.

04Nineteen attempts
Blocked — stripped by the filter (fails gate i) Inert — survives, but won't auto-run (fails gate ii) Bypass — clears both
05The abruptly-closed comment

The whole exploit rides on <!-->. The HTML spec calls this an abrupt-closing of an empty comment: a comment opened with <!-- that is immediately followed by > ends right there. BeautifulSoup's lenient parser does not — it keeps consuming until -->.

◆ BeautifulSoup sees

One comment node: everything from <!-- to --> inclusive.

The <img> and its onerror live inside the comment. find_all(True) never visits comment nodes, so Rule 03 never runs on it. The file is written back unchanged.

◆ The browser sees

<!--> is a complete, empty comment. It closes at the first >.

What follows is live markup: <img src=x> requests a resource named x, fails, and fires onerror → alert('XSS Bypass!'). The trailing --> is harmless text.

06Verified after filtering

The agent copied out.html, ran the real filter.py over the copy, then drove the sanitized output through the headless test harness.
