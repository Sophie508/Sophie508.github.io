What the filter kills

from trajectory recon
  • drop tag
    <script> — every script, any type, any nesting. soup("script")
  • drop tag
    <frame> <iframe> <object> <embed> — whole subtree gone.
  • strip attr
    Any attribute whose lowercased name startswith("on") — onclick, onerror, onload, onLoad, onmouseover…
  • blind spot
    HTML Comment nodes are not walked as tags. Contents inside comments are never attribute-sanitized.

First empirical proof: <svg onload=…> returned as bare <svg></svg>. Later, ev:onload and RLO-prefixed names survived the prefix check but never executed in a browser.

Sanitizer sketch

behavioral model 
# /app/filter.py — behavior recovered from the run
from bs4 import BeautifulSoup

def filter_html(path):
    soup = BeautifulSoup(open(path), "html.parser")

    for tag in soup("script"):
        tag.decompose()           # kill scripts

    for name in ("frame","iframe",
                 "object","embed"):
        for tag in soup(name):
            tag.decompose()

    for tag in soup.find_all(True):
        for attr in list(tag.attrs):
            if attr.lower().startswith("on"):
                del tag.attrs[attr]  # strip handlers

    open(path,"w").write(str(soup))  # in-place
Crucial: find_all(True) only yields tags. Comment nodes sit outside that walk — payload sanctuary if the browser later un-comments them.

Why this beats the filter

parser differential
Root cause: sanitizer and consumer do not share a parse tree. BeautifulSoup’s comment opacity + the browser’s comment termination rules create a split-view object that is “data” to one and “DOM + handler” to the other.
  1. Exhausts in-DOM vectors (on*, script, iframe, meta javascript:, CSS, RLO, namespaced attrs).
  2. Step 105: comment containing a hostile <img onerror> is emitted unchanged.
  3. Adjust terminator from <!-->…<--> to <!-->…--> so the browser exposes the image node.
  4. test_outputs.py confirms alert text 'XSS Bypass!'.
