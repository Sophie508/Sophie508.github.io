Issue Frame

The case centers on a specification mismatch: boolean operator sequences should not inherit the current nesting depth when scored.

01

Observed behavior

The existing `test_real_function()` expected 11, because nested bool operations were multiplied by the nesting increment.

02

Specification cue

Sequences of binary logical operators receive a fundamental increment, B1, but not nesting increment B3.

03

Target outcome

The multiline condition in `process_raw_constant` should contribute +2, making the final complexity 9 instead of 11.

Repair Path

The trajectory is a compact debugging loop: locate the failing test, trace through the API, adjust BoolOp accounting, then update expectations exposed by the new rule.

Search

Found the failing surface

`test_real_function` was located in `tests/test_cognitive_complexity.py` after the first literal function search missed it.

Trace

Followed the calculator

The investigation moved from `tests/conftest.py` to `cognitive_complexity/api.py`, then into `cognitive_complexity/utils/ast.py`.

Fix

Removed nesting from BoolOp base complexity

The multiplication by `max(increment_by, 1)` was replaced with a plain count of bool operation sequences.

Recover

An assertion edit was attempted while the AST utility file was open; the editor rejected it, and the agent reopened the test file.
