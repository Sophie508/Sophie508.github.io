Case anatomy

Issue, trajectory, and patch

Reported behavior

Profiling a benchmark against the existing environment fails because the command treats the configured/default revision as though the user explicitly requested one.

$ asv profile -E existing
comm.Transfer.time_tcp_large_transfers_uncompressible
· An explicit revision may not be specified when using an existing environment.

Alternative forms

The report says --python=same fails identically. It also notes that asv run --python=same --profile does not appear to save profile output anywhere.

$ asv profile --python=same …
· An explicit revision may not be specified …

$ asv run --python=same --profile -b …

Relevant control flow

The inspected code first replaces a missing revision with conf.branches[0], then later checks revision is not None. By that point the check can no longer distinguish a user-supplied revision from the default it just assigned. The agent noticed the guard, but its patch keyed off the raw environment specification string instead of resolving this state distinction robustly.

01

Symptom, not state model

The patch checks whether env_spec literally equals existing. That does not cover the reported --python=same form and ignores the existing is_existing_only(environments) abstraction already used above.

02

Evidence was not incorporated

Identical failures after each change should have triggered source tracing for argument normalization or confirmation that the edited code was the code being executed. Instead, nearly the same edit was repeated.

03

Potential regression introduced

Removing env.install_project for all paths in this block—not just existing environments—can skip required setup for normal managed environments.

04

No tests added

The issue has two option forms and revision semantics suitable for focused command tests. The trajectory shows neither new tests nor an existing relevant test suite run.

05

Output concern untouched

The report’s secondary concern—where asv run --profile stores profile data—was not investigated or addressed.

06

Evaluation unavailable

eval_logs and target were stripped from this case. The review therefore judges only the visible trajectory and patch, not hidden benchmark results.

What a stronger repair process needed

Preserve whether the revision was explicitly supplied before applying a default; use the resolved environment capability/type rather than a single raw option spelling; keep installation behavior intact for installable environments; add coverage for both -E existing and --python=same; then run focused tests plus the original reproductions. This is a process-level assessment, not a claim about the unseen gold patch.
