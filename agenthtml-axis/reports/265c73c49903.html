bihealth / biomedsheets · issue #23

A single hyphen stopped a whole-genome run.

A germline sample sheet used a patient name like test-patient-1. The parser rejected the dash outright — and with it, the entire sequencing pipeline. The agent's job: retire a validation rule that had outlived its purpose.

patientName column · as read by the validator test-patient-1
01

What broke SODAR sample sheets permit hyphens in the patient column. biomedsheets did not — so valid data from one system was fatal in the next.

On 15 Feb 2022, an Aortopathy WGS run failed at sheet-loading time. Snakemake never reached a single mapping job. The traceback ends in one guard clause deep inside the TSV reader.

Did it land? The reported failure is gone. The manner of the fix leaves loose ends a reviewer would likely flag.

Resolved

The behaviour is fixed

  • Root cause found precisely — traceback → file → method → line, no wandering.
  • Verified end to end — a hyphenated name now passes the full reader, not just the edited branch.
  • Scoped correctly — patient, father, and mother guards all lifted, matching the maintainer's intent.
Loose ends

What a reviewer would question

  • Dead code left behind — the guards are commented out, not deleted. Cleaner to remove them.
  • Duplicated comment — the edit re-adds “# Check for hyphen…”, leaving it twice.
  • No lasting test — the reproduction was a scratch file, deleted before submit; nothing guards against regression.
