  6. 6 The full analysis: latest release per package, stars parsed from prose, top 5 ok · 2.6 s · 23:27:32 Produced the ranked list shown at the top of this page. The script is reproduced here as the agent wrote it, with shell escaping removed.

    script

    import sqlite3, duckdb, json, re

# Latest release per distinct NPM package (registry ordinal is release order).
s = sqlite3.connect("file:data/package_query.db?mode=ro&immutable=1", uri=True)
s.execute("pragma temp_store=memory")
latest = {}
for name, version, version_info in s.execute(
        "select Name, Version, VersionInfo from packageinfo where System = ?", ("NPM",)):
    info = json.loads(version_info)
    if info.get("IsRelease"):
        ordinal = info.get("Ordinal", -1)
        if name not in latest or ordinal > latest[name][0]:
            latest[name] = (ordinal, version)
s.close()

# Parse GitHub project names and star counts, then map latest package versions to them.
d = duckdb.connect("data/project_query.db", read_only=True)
project_stars = {}
for text, in d.execute("select Project_Information from project_info").fetchall():
    pm = re.search(r"^The project (.+?) (?:is hosted on GitHub|on GitHub)", text or "")
    sm = re.search(r"([0-9][0-9,]*) stars?", text or "")
    if pm and sm:
        project_stars[pm.group(1)] = int(sm.group(1).replace(",", ""))

rows = []
for system, name, version, project in d.execute(
        "select System, Name, Version, ProjectName from project_packageversion where System = ?", ["NPM"]).fetchall():
    if name in latest and version == latest[name][1] and project in project_stars:
        rows.append((project_stars[project], name, version, project))
d.close()

# A package may have duplicate mappings; rank each package once by its highest-star GitHub project.
best = {}
for stars, name, version, project in rows:
    if name not in best or stars > best[name][0]:
        best[name] = (stars, version, project)
answer = sorted(((v[0], n, v[1], v[2]) for n, v in best.items()), key=lambda x: (-x[0], x[1]))[:5]
print("Top 5 latest NPM package releases by GitHub stars")
for rank, (stars, name, version, project) in enumerate(answer, 1):
    print(f"{rank}. {name} @ {version} — {stars:,} stars ({project})")

Where to look twice

These are places where the recorded method could change the top 5 without any error showing in the log. None of them was measured during the run.

  • The star parser drops some projects, and the agent’s own sample proves it.

    The pattern requires a number followed by the word “stars”. The fourth sampled project reads “a stars count of 3761”, which does not match, so leaflet.markercluster is silently absent from the ranking. One of five sampled sentences failing means an unknown share of the 8,381 projects was never ranked. A high-star upstream with that wording would be missing from the answer.

  • Packages whose latest version is not in the mapping table vanish.

    A package is only ranked when the exact version string chosen as latest also appears in the DuckDB mapping table. The mapping table has 63,770 fewer rows than the package table. Nothing in the run checked how many packages this excluded.

  • “Latest” means highest registry ordinal, pre-releases excluded.

    This is a reasonable reading and it is the one the agent stated in its final message. It was not compared against the publish timestamp column, so an ordinal that disagrees with publish date would go unnoticed.

  • Relation type was ignored when a package maps to several projects.

    The mapping table carries RelationType and RelationProvenance columns, which distinguish for instance a source repository from another kind of link. The agent kept whichever mapped project had the most stars, without looking at these columns.

  • The winners are scoped forks that borrow upstream stars.

    Every listed package is a namespaced republish, for example a package named @dylanvann/svelte mapped to the sveltejs/svelte repository. Two of the five map to the same repository and tie at 39,660 stars, broken alphabetically. The question asks for packages, and these are packages in the data, but a grader expecting the canonical svelte or tailwindcss package would score this differently.

  • Half of the run’s commands failed before any analysis happened.

    Commands 1, 3 and 4 failed on sandbox and SQLite I/O limits. Each failure was diagnosed correctly and fixed on the next try, and no file was written. The failures cost about 20 seconds and did not affect the result.
