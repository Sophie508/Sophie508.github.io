Features
Capabilities

Everything needed for multitask molecular prediction

A dependency-free pipeline that transforms raw SMILES into competitive dual-task predictions without requiring specialized cheminformatics libraries.

🧬

SMILES N-Gram Hashing

Character n-grams (2–5 chars) are hashed into a 16,384-dimensional sparse vector using scikit-learn's HashingVectorizer — capturing recurring atoms, bonds, and ring markers without RDKit.

🎯

Multitask Classification

MultiOutputClassifier wraps two LogisticRegression heads sharing the same feature matrix, jointly predicting FDA_APPROVED and CT_TOX from a single featurization pass.

⚖️

Class Balancing

Built-in class_weight="balanced" prevents the rare toxic (CT_TOX=1) and non-approved classes from being drowned by the majority — critical for imbalanced drug data.

🔒

No Data Leakage

HashingVectorizer is stateless, so it cannot memorize or leak test-set vocabulary. The featurizer is fit-free and applies identically to train and test.

📊

Rich Prediction Output

Predictions CSV includes true labels, predicted labels, and positive-class probabilities for both tasks — supporting thresholding and downstream analysis.

⚡

Fast & Reproducible

Entire training and evaluation completes in under 3 seconds with a fixed random_state=42, producing deterministic, reproducible results every run.

Implementation

The complete training script

A single self-contained Python file — no chemistry libraries, no GPU, no fuss.

train_clintox_multitask.py 
"""Train and evaluate a multitask classifier on the ClinTox dataset.

SMILES are represented by character n-gram hashing, which requires no chemistry-
specific dependency. Both output classifiers consume the same molecular feature
matrix and are fitted together through scikit-learn's MultiOutputClassifier.
"""

from pathlib import Path

import pandas as pd
from sklearn.feature_extraction.text import HashingVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, classification_report
from sklearn.multioutput import MultiOutputClassifier


ROOT = Path(__file__).resolve().parent
TRAIN_CSV = ROOT / "clintox" / "clintox_train.csv"
TEST_CSV = ROOT / "clintox" / "clintox_test.csv"
PREDICTIONS_CSV = ROOT / "clintox" / "clintox_test_predictions.csv"
TARGETS = ["FDA_APPROVED", "CT_TOX"]


def load_data(path: Path) -> pd.DataFrame:
    """Load a ClinTox split and validate the required columns."""
    data = pd.read_csv(path)
    required = {"smiles", *TARGETS}
    missing = required.difference(data.columns)
    if missing:
        raise ValueError(f"{path} is missing columns: {sorted(missing)}")
    if data[list(required)].isna().any().any():
        raise ValueError(f"{path} contains missing SMILES or target values")
    return data


def main() -> None:
    train = load_data(TRAIN_CSV)
    test = load_data(TEST_CSV)

    # Local SMILES patterns function similarly to hashed substructure features.
    # HashingVectorizer is stateless, so it cannot leak test-set information.
    featurizer = HashingVectorizer(
        analyzer="char",
        ngram_range=(2, 5),
        n_features=2 ** 14,
        alternate_sign=False,
        norm="l2",
        lowercase=False,
    )
    x_train = featurizer.transform(train["smiles"])
    x_test = featurizer.transform(test["smiles"])
    y_train = train[TARGETS].astype(int)
    y_test = test[TARGETS].astype(int)

    # Class balancing prevents the rare toxic/non-approved classes from being
    # ignored. MultiOutputClassifier fits one head per task on shared features.
    model = MultiOutputClassifier(
        LogisticRegression(
            class_weight="balanced",
            solver="liblinear",
            max_iter=2000,
            random_state=42,
        )
    )
    model.fit(x_train, y_train)
    predictions = model.predict(x_test)

    print(f"Training rows: {len(train):,}; test rows: {len(test):,}")
    print(f"Hashed feature dimensions: {x_train.shape[1]:,}")
    for index, target in enumerate(TARGETS):
        accuracy = accuracy_score(y_test.iloc[:, index], predictions[:, index])
        print(f"\n{target} accuracy: {accuracy:.4f}")
        print(classification_report(..., digits=4, zero_division=0))

    output = pd.DataFrame({
        "smiles": test["smiles"],
        "FDA_APPROVED_true": y_test["FDA_APPROVED"],
        "FDA_APPROVED_pred": predictions[:, 0],
        "CT_TOX_true": y_test["CT_TOX"],
        "CT_TOX_pred": predictions[:, 1],
    })
    for index, target in enumerate(TARGETS):
        output[f"{target}_probability"] = model.estimators_[index].predict_proba(x_test)[:, 1]

    PREDICTIONS_CSV.parent.mkdir(parents=True, exist_ok=True)
    output.to_csv(PREDICTIONS_CSV, index=False)
    print(f"Predictions saved to: {PREDICTIONS_CSV}")


if __name__ == "__main__":
    main()
FAQ

Common questions

Technical details about the approach and design decisions.

Why use character n-gram hashing instead of molecular fingerprints?
RDKit was not available in the execution environment. Character n-gram hashing via HashingVectorizer captures recurring SMILES patterns — atoms, bonds, ring markers, and local substructures — as a sparse vector without any chemistry-specific dependency. It's stateless (no fit step), so there's zero risk of vocabulary leakage from test to train.
How does multitask learning work here?
scikit-learn's MultiOutputClassifier wraps a separate LogisticRegression estimator for each target column. Both heads consume the identical feature matrix, so the featurization is shared while the decision boundaries are independent. This is a lightweight form of multitask learning — shared representation, separate task heads.
Why is class_weight="balanced" important?
The ClinTox dataset is heavily imbalanced: only ~6% of molecules are toxic (CT_TOX=1) and ~8% are non-FDA-approved. Without balancing, the model would achieve high accuracy by always predicting the majority class, ignoring the rare but clinically critical toxic/non-approved cases. Balanced class weights reweight the loss to give minority classes equal influence.
What's in the predictions CSV?
The output file (297 rows, 7 columns) contains: the original SMILES string, true and predicted labels for both FDA_APPROVED and CT_TOX, plus positive-class probabilities for each task. The probabilities enable custom thresholding — e.g., lowering the CT_TOX decision threshold to increase recall on toxic compounds at the cost of precision.
How long does training take?
The entire pipeline — data loading, featurization, multitask training, evaluation, and prediction export — completes in under 3 seconds on a standard CPU. No GPU or specialized hardware is required. The run used a fixed random_state=42 for full reproducibility.
