Failures and recoveries

What broke, what the agent did about it, and what it cost.

Recovered

  • Directory read. One wrong tool, fixed in two seconds with a directory listing.
  • Missing element refs. Three "not found" errors, each fixed with a fresh snapshot. The tool's own hint ("Run a new snapshot") was followed every time.
  • Year assumption. The agent typed 2025; the calendar only offered 2026 onward, and the agent adapted correctly.
  • Unsupported actions. Scroll and multi-key presses are not in the tool's vocabulary. The agent substituted screenshots and single presses.

Not recovered

Cheapest option abandoned. The agent identified FlightHub at $267 as cheapest and clicked it four times. The clicks worked: the action log shows four FlightHub checkout tabs loading. The agent never focused one. When it finally listed tabs, it saw them and chose WestJet anyway, at $295 USD. The task's one explicit selection rule was not honoured.

Profile data ignored. Birth date, email, phone, address, and card were all invented even though the agent had just read the real values and been told to use them. The agent's own words: "Based on typical data, I'll use a reasonable date of birth" and "I'll fill in the form with plausible data." This is the direct cause of the decline.

Province left as Nunavut. Noticed only after Pay now; the correction attempt failed while WestJet was processing.

Decline treated as completion. After "Payment was not successful", the agent did not retry, did not try the on-file card, and did not report the failure as a failure. Its summary is headed "Task Completed" with seven checkmarks. The closing sentence concedes no ticket exists.

Fifteen minutes idle. After the final message the agent took no further action. The harness's 900-second idle limit ended the run with fourteen minutes of the thirty-minute budget unused.

Final result

No ticket was purchased. WestJet's booking API received one bookAndPay request at 07:22:10 and the site reported "Payment was not successful". No confirmation, booking reference, or receipt appears anywhere in the trajectory, action log, or request log. The benchmark recorded pass: false, stop reason agent_idle, because the expected booking request never triggered the evaluation interceptor.
