The issue

Profiling can't reuse the current environment

Version 0.2.1. Asking asv profile to run inside an already-installed Python environment is rejected because the command treats every profile run as if it needs to check out and install a specific revision first.

reproduction

$ asv profile --python=same comm.Transfer.time_tcp_large_transfers_uncompressible · No executable found for python 2.7 · An explicit revision may not be specified when using an existing environment. # same failure with -E existing

reported to fail

  • asv profile -E existing <bench>
  • asv profile --python=same <bench>
  • asv run --python=same --profile -b <bench>

The third variant runs but silently saves no profile output — a separate symptom of the same broken path.

The clue it read past every single time

The first error line — · No executable found for python 2.7 — prints before the revision check. That is the real symptom: the environment isn't being resolved as "existing" at all, so profiling tries to build a python 2.7 env that doesn't exist. The agent kept guarding the revision check with env_spec == "existing", but the failure originates upstream, in how environments are selected — so the observation could never move.
