01 / The change in context

Valid upstream. Rejected downstream.

The issue reports biomedsheets 0.11.1 rejecting hyphens accepted by SODAR, interrupting a genomic pipeline while loading a germline sample sheet.

01 / TRIGGER

A name becomes an error

patientName containing a hyphen raises GermlineTSVSheetException in check_tsv_line(). The supplied stack trace points to the germline TSV reader.

SOURCE · task/task_statement.md
02 / INTERVENTION

Three guards commented out

The agent disables hyphen checks for patientName, fatherName, and motherName. Library type, sex, and affected-status checks remain active.

SOURCE · generated_patch
03 / CONFIDENCE

A narrow observed success

A temporary fixture with test-patient-1 loads. Parent names are both 0, so hyphenated parent references are not exercised. No retained regression test is submitted.

The record supports a successful read of one corrected, hyphenated-patient fixture. Broader compatibility and benchmark resolution are unverified in the supplied material.

What does the outcome establish?

The final local script reaches its success print after reader.read_sheet(). The top-level exit_status is submitted. These are separate observations; no evaluator verdict is supplied.

What remains untested?

Hyphenated father and mother names, parent-reference resolution, the repository test suite, and the original pipeline are not tested in the visible run. The initial fixture was created only after the source change.

Why was this restriction present?

The issue attributes it to unambiguous splitting of identifiers shaped like SAMPLE-NORMALTUMORNUMBER-EXTRACTIONNUMBER-LIBRARYNUMBER. The trajectory does not investigate downstream consumers of that convention.
