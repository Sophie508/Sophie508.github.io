01

The malfunction

Profiling a benchmark against an already-installed environment refuses to launch — even though the user never named a revision.

$ asv profile -E existing comm.Transfer.time_tcp_large_transfers_uncompressible An explicit revision may not be specified when using an existing environment.
$ asv profile --python=same comm.Transfer.time_tcp_large_transfers_uncompressible An explicit revision may not be specified when using an existing environment.

Reported against asv 0.2.1. The user passed no revision — yet the tool insists one was given.

02

The holding pattern

Waypoints of a stuck agent

The agent circled a fixed four-step loop: edit line 156, re-run the command, read the identical error, then re-open the file and edit again.

Each lap widened the edit range — 156:161 → 156:200 — but never left the same region of code, and never questioned whether that region was the real fault.

Never landed: the runway it needed was 30 lines up.

Root cause · line 125–126

When no revision is passed, the code quietly defaults revision to the current branch. From that point on it is never None — so the “explicit revision” it complains about is one the code itself invented.

The symptom the agent fixated on · line 156

The guard reads if revision is not None, then bails on any environment that can’t install a project — exactly the existing / --python=same case. The agent rewrote this eight times; the truth is it should have keyed off whether the user actually supplied a revision, decided 30 lines earlier.

What it submitted

The patch compares env_spec — a list of environment selectors — against the bare string "existing", which never matches. It leaves --python=same untouched, and quietly deletes env.install_project, which would break ordinary profiling. It does not compile the bug away.

06

Debrief

Missed Why it never landed

The agent treated the error message as the bug and hunted for a flag to suppress it — never tracing why revision was non-None when the user passed nothing.

  • Read the guard, not the assignment that fed it 30 lines above.
  • Assumed env_spec was a string; it is a list of selectors.
  • Ignored --python=same entirely — the second failing case.
  • Re-ran an unchanged strategy 8 times instead of re-diagnosing after the first failure.

Runway The landing it needed

Distinguish a revision the user chose from one the code defaulted. Capture that intent before line 126 overwrites it:

  • Remember whether revision was supplied before defaulting to the branch.
  • Raise the “explicit revision” error only when the user really named one and the environment can’t install.
  • Let existing / same-Python environments profile in place — keeping install_project for every other path.
