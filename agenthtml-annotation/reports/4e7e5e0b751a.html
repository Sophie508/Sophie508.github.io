Why the exact match failed

None of the four catalog rows stores the bare title "Get Me Bodied". Each source wrapped it with album text, a track number prefix, or the artist name, and one row has no artist at all. An exact equality on title was therefore guaranteed to miss, independent of the accent in "Beyoncé".

What the matching rule accepted

Title contains "get me bodied" (case-insensitive) AND either the artist is exactly "beyoncé"/"beyonce" or the title itself contains either spelling. All four rows passed. The rule was not applied to the album column, and no other artist was found to share the title in the independent read.

Failures and recoveries

Two setbacks, both recovered within the same turn. Neither was hidden from the user, though only the first was narrated.

Failure 1 · sandbox blocked the heredoc

The read-only sandbox rejected the shell's temp file for a heredoc. Zero Python executed on the first attempt.
Recovered The agent explicitly told the user it was switching to an inline command, then reissued the same schema dump as a python -c one-liner. Every later command used the same pattern.

Failure 2 · exact match produced $0.00

The first aggregation matched no tracks and printed a zero total. Reporting this value would have been wrong.
Recovered The agent did not narrate this pivot but immediately ran a substring search, found four noisy variants, broadened the artist condition, and recomputed. The $0.00 was never presented as an answer.
