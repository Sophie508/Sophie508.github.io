02 / Method

Two stores. One join path. Four moves.

STEP 01

Inspect schemas

Identify packageinfo, project_packageversion, and project_info.

STEP 02

Resolve latest

Keep rows where IsRelease is true; retain the greatest registry Ordinal per package.

STEP 03

Parse popularity

Extract project names and integer star counts from the descriptive Project_Information text.

STEP 04

Map & rank

Match exact package versions to projects, deduplicate packages by their highest-star mapping, then sort descending.

analysis.py · distilled from trajectory
# Latest release = greatest registry ordinal
latest = {}
for name, version, raw in sqlite_rows:
    info = json.loads(raw)
    if info.get("IsRelease"):
        ordinal = info.get("Ordinal", -1)
        if name not in latest or ordinal > latest[name][0]:
            latest[name] = (ordinal, version)

# Keep the strongest project mapping per package
best = {}
for stars, name, version, project in mapped_rows:
    if name not in best or stars > best[name][0]:
        best[name] = (stars, version, project)

answer = sorted(
    ((v[0], n, v[1], v[2]) for n, v in best.items()),
    key=lambda x: (-x[0], x[1])
)[:5]

05 / Caveats

What to remember before reusing the result.

Stars live in prose

The DuckDB schema has no dedicated numeric star field. The analysis uses regular expressions against Project_Information; unseen sentence forms could be skipped or misread.

Packages ≠ projects

Ranking is package-centric, but popularity comes from mapped repositories. Two different packages in positions four and five both inherit 39,660 stars from the same styled-components project.

“Latest” means ordinal

The run defines the latest release as the row with the greatest registry Ordinal among rows marked IsRelease, rather than comparing semantic versions or publish timestamps.
